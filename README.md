# Цифровой деканат — личный кабинет студента

Концепт для номинации «Вайб-кодинг» конкурса MGIMO×AI Challenge 2026.
**Это не официальный сервис вуза.** Все люди, группы, оценки и заявки в демо-данных вымышлены.

**Прототип: https://dekanat-zemelor.msk1.amvera.tech** (открывается из России без VPN).

Рабочий прототип, а не макет: настоящий сервер, база данных, вход по паролю, разграничение доступа.
Удобно открывать с телефона (от 360 px), на компьютере появляется боковое меню.

| Раздел | Что видит студент |
|---|---|

Калькулятор «Что если»: сколько наберёте за оставшиеся точки и что это даст. Расписание сессии, долги и пересдачи, прошлые сессии со средним баллом. |
| **Заявки и справки** | Заказ справки или заявления онлайн с проверкой полей. Ссылка в коде случайная, а страница проверки показывает только номер, дату, инициалы и факультет. |
| **Уведомления** | Новости деканата, изменения в расписании, смена статуса заявки, напоминания о дедлайнах на 3 недели вперёд. Фильтры, отметка «прочитано». |

Кабинет можно **установить на телефон как приложение** (PWA): своя иконка, запуск без адресной строки, понятная страница «Нет соединения» без интернета. Кнопка установки — в профиле, на iPhone — «Поделиться → На экран „Домой“». Service worker кеширует только общие статические файлы, страницы с личными данными всегда приходят с сервера.

Есть и **кабинет сотрудника деканата**: очередь заявок с поиском, смена статуса (студенту сразу приходит уведомление; отказать без причины нельзя), рассылка новостей отдельной группе или всем студентам.

Для демонстрации пересдачи войдите как `student2`, на главной найдите «Ближайшая пересдача» и нажмите «Открыть готовое направление». В карточке нажмите «Открыть»: появится учебный документ по теории вероятностей.

## Тестовые аккаунты

Два студента с разной ситуацией и сотрудник деканата: `student1`, `student2`, `dekanat`.
Пароли указаны в отдельном поле тестовых аккаунтов конкурсной заявки и в репозиторий не попадают: в коде лежат только их bcrypt-хеши.

## Безопасность и данные

- **Пароли** хранятся только как bcrypt-хеш. В коде, в браузере и в репозитории открытых паролей нет.
- **Сессия** — случайный токен в cookie с флагами `HttpOnly`, `SameSite=Lax`, а по HTTPS ещё и `Secure`. В базе хранится только SHA-256 от токена, срок жизни 7 дней. Выход удаляет сессию на сервере.
- **Чужие данные не открыть подменой адреса.** Каждый запрос к заявке, справке или уведомлению проверяет на сервере, что запись принадлежит вошедшему студенту. На чужой номер сервер отвечает 404, как будто записи нет. Студент на страницах сотрудника получает 403.
- **Подбор пароля**: после 5 неудачных попыток за 10 минут вход для этой пары «адрес + логин» блокируется. Сообщение одинаковое для неверного логина и неверного пароля, время ответа тоже одинаковое.
- **CSRF**: у каждой формы скрытый токен сессии, плюс проверка заголовка `Origin`.
- **XSS**: шаблоны экранируют всё, что ввёл пользователь. Строгая политика CSP: только свои скрипты и стили, без inline-кода. Запрет встраивания во фреймы, `nosniff`, `Referrer-Policy`, HSTS.
- **Данные** лежат в SQLite в постоянном томе хостинга. При пустой базе загружаются демо-данные, даты демо-событий рассчитываются от первого запуска. Подключение PostgreSQL потребует драйвера, настройки и переноса данных. Проверенный вариант — SQLite.

## Запуск локально

Нужен Python 3.11+.

```powershell
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000
```

Откройте http://localhost:8000. Чтобы задать свои пароли для демо-аккаунтов, перед первым запуском положите bcrypt-хеши в переменные окружения `DEMO_HASH_STUDENT1`, `DEMO_HASH_STUDENT2`, `DEMO_HASH_DEKANAT`.

Автотесты (39 проверок: разделы, разделение данных, CSRF, ограничение попыток входа, заголовки, полный цикл заявки):

```powershell
python -m pip install pytest httpx
python -m pytest -q
```
